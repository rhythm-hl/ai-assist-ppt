Problem Statement

What's broken today and why it matters

Context

What is IATF?

The Internal Actions & Triggers Framework (IATF) is a UI-based platform that enables developers to create and configure workflow actions and triggers — without writing custom backend logic for each one.

🎛️
Dynamic Configuration
Instead of hardcoding behavior, IATF lets developers define actions and triggers through a configurable UI, enabling rapid creation with dynamic input fields, validation rules, and API mappings.
⚡
Workflow Foundation
IATF is the backbone of workflow automation, powering the actions and triggers that users rely on to build their business processes inside HighLevel.
🔌
Integration Apps
Beyond internal workflows, IATF now also powers all integration apps, enabling third-party integration actions and triggers work with HighLevel.
📈
Scale & Flexibility
With 200+ actions and triggers already built, IATF has proven its ability to scale, but this growth has also exposed the limits of the manual configuration process.
Problem

Building IATF Integrations is Still Painful

While IATF provides a UI-based platform, the process of creating integrations remains tedious — developers must understand a wide range of configuration options, manually research third-party APIs, and configure every part of an action or trigger by hand.

Steep Learning Curve
The platform exposes dozens of configuration options — input field types, validation rules, dynamic sources, and more. Developers need to know most of them to build correctly.
API Research Overhead
Every third-party integration requires researching the correct endpoints, HTTP methods, request schemas, and authentication flows before configuration can even begin.
Manual, Part-by-Part Configuration
Each section of an action — inputs, API mapping, key format, variable prefix — must be configured individually through the UI, making the process slow and repetitive.
V1 AI Agent — Limited Help
A first version of an AI agent existed, but it only supported one-time generation with no ability to update or iterate. Accuracy was low, so it provided a rough starting point at best — significant manual effort was still required.

02

Proposed Solution

Our approach and key design decisions

Solution

AI-Powered Conversational Builder

Describe integrations in natural language. Get complete, valid IATF configurations automatically.

💬
Natural Language → Config
"Build a Zoom create-meeting action" produces a complete, save-ready action JSON with all required fields.
⚡
Multi-Build
"Create an Airtable app with CRUD actions and a new-record trigger" — generates everything in a single turn.
🔧
Modify Existing
"Add a description input to the Slack send-message action" — fetches existing config and returns updated version.
🔄
Self-Healing Saves
When a save fails validation, the error is automatically fed back to the agent, which fixes and re-proposes.
Solution

Why This Approach?

Design Decisions

  • LangGraph over a single prompt — agentic loop lets the LLM discover existing patterns before generating configs
  • RAG-powered knowledge retrieval — dynamically loads the relevant knowledge base documents based on the user's requirements, ensuring the agent always has the right context
  • Agent never asks technical questions — only asks about business intent, researches APIs and schemas itself
  • Structured clarifications — interactive forms with selectable options, not free-text back-and-forth

Why Not Alternatives?

  • Template-based codegen: Too rigid — can't handle the variation across 200+ integrations and arbitrary API shapes
  • Single-shot prompt: Lacks context — can't inspect existing actions or search docs mid-generation

Technical Deep Dive

Architecture, AI/tooling choices, and stack integration

Architecture

High-Level Architecture

Architecture

Agent Tools & Knowledge Base

The agent is equipped with specialized tools to discover existing patterns and a RAG-powered knowledge base to ground its output in real documentation.

Agent Tools

  • fetch_existing_action / trigger — retrieve a saved config by name
  • list_sections — browse available integration app sections
  • list_actions / triggers — list all actions or triggers within a section
  • find_similar_actions / triggers — discover similar patterns to use as reference
  • search_documentation — query the knowledge base for relevant schema and API docs

Knowledge Base (RAG)

  • MongoDB Atlas vector search for semantic document retrieval
  • OpenAI text-embedding-3-small for embedding generation
  • Structure docs — IATF schema reference and field definitions
  • Per-app API docs — third-party API documentation for each integration
